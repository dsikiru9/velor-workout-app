You are building a complete personal workout application called VELOR.

IMPORTANT: READ THE ENTIRE SPECIFICATION BEFORE BUILDING.

VELOR IS A NORMAL WORKOUT APP.

It is NOT a calisthenics app.

Do not describe, brand, market, or structure VELOR as a “calisthenics” application. The fact that many exercises use bodyweight does NOT make the product a calisthenics app.

VELOR is a progressive workout application designed around the equipment, furniture, space, and physical ability that the user actually has available at home.

==================================================
1. PRODUCT IDENTITY
==================================================

App name:

VELOR

VELOR should feel like a modern, serious workout/fitness application.

The experience should be simple:

Choose a body area
→ choose a level
→ start workout
→ see the exercise demonstration
→ read how to perform it
→ complete sets/reps/time
→ rest
→ continue
→ finish workout
→ save progress.

Do not make the interface look like a bodybuilding encyclopedia, a calisthenics community, or a gymnastics training platform.

The focus is practical workout progression.

==================================================
2. AVAILABLE EQUIPMENT / RESOURCES
==================================================

Do NOT assume the user has a gym.

The user has access to:

- Open floor space
- A chair
- A window iron/grille that can potentially be used for appropriate exercises
- Walls
- Their own bodyweight

Therefore exercises MAY use:

- Bodyweight
- Floor
- Chair
- Wall
- Secure window iron/grille

However:

SAFETY IS CRITICAL.

Never assume a window grille, chair, wall, or other household object is structurally safe.

For exercises involving a chair:
- Require a stable chair.
- No rolling chair.
- No unstable/light furniture.
- Include a short safety cue where appropriate.

For exercises involving window iron/grilles:
- Only include movements where the structure can reasonably support the user's weight.
- Clearly instruct the user to verify stability before attempting the movement.
- Do NOT design exercises that require dangerous climbing, hanging from an uncertain structure, or putting the user at unnecessary risk.

The app should never require specialized gym equipment such as:
- Barbells
- Dumbbells
- Kettlebells
- Cable machines
- Resistance machines
- Resistance bands
- Benches
- Pull-up stations
- Gym machines

unless the user later explicitly adds equipment.

==================================================
6. EXERCISE PROGRAMMING
==================================================

Each level should contain approximately 4–6 exercises.

Each exercise must have:

- Exercise name
- Target body area
- Sets
- Repetitions OR duration
- Rest period
- Difficulty
- Equipment/resource required
- Exercise demonstration
- Step-by-step instructions
- Form cues
- Common mistakes
- Muscles primarily involved
- Easier regression where appropriate
- Harder progression where appropriate

Example structure:

EXERCISE:
Chair-Assisted Split Squat

SETS:
3

REPS:
8–10 each leg

REST:
30 seconds

RESOURCE:
Chair

HOW TO PERFORM:
1. Stand in a stable position beside/in front of the chair.
2. Place the appropriate body part/hand lightly on the chair only for balance if the exercise calls for it.
3. Lower under control.
4. Keep the knee tracking appropriately.
5. Push through the working leg to return to the starting position.

FORM CUES:
- Keep the torso controlled.
- Do not collapse the knee inward.
- Move through a comfortable range.

COMMON MISTAKES:
- Losing balance
- Rushing the descent
- Knee collapsing inward

REGRESSION:
Supported split squat

PROGRESSION:
Unassisted split squat / more demanding variation

Do NOT use generic instructions such as:
“Perform the exercise with proper form.”

The instructions must actually explain the movement.

7. REAL PROGRESSION ACROSS ALL 22 LEVELS
==================================================

The 22 levels must form a coherent progression.

BEGINNER:

Levels 1–7 should establish:

- Movement fundamentals
- Basic strength
- Basic endurance
- Joint control
- Familiarity with movements
- Simple variations
- Appropriate use of chair/wall/floor where useful

INTERMEDIATE:

Levels 8–14 should introduce:

- More demanding variations
- Greater range of motion
- Increased volume
- Slower tempo
- Pauses
- Unilateral work
- Reduced assistance
- More demanding combinations
- Greater stability requirements

ADVANCED:

Levels 15–22 should introduce:

- High-demand variations
- Advanced unilateral work
- Longer time under tension
- Difficult leverage
- Complex combinations
- Controlled explosive work where appropriate
- Greater volume/density
- More demanding stability and coordination

Do not introduce an advanced exercise simply because it sounds impressive.

Progression must make physiological and mechanical sense.

8. REAL EXERCISE DEMONSTRATIONS
==================================================

THIS IS ONE OF THE MOST IMPORTANT REQUIREMENTS.

Every exercise must have a practical visual demonstration.

The visual must show a REALISTIC HUMAN BODY PERFORMING THE MOVEMENT.

The user needs to be able to look at the visual and understand:

- Starting position
- Movement
- Ending position
- Direction of movement
- Body positioning

Preferred format:

Animated GIF

Second preference:

Short looping MP4/video

Third preference:

Another high-quality platform-supported animated exercise demonstration.

DO NOT use:

- Tiny SVG stick figures
- Static rectangles
- Placeholder boxes
- Emoji
- Text saying “GIF”
- A generic human icon
- A simple arrow animation pretending to demonstrate the exercise

The demonstration needs to actually demonstrate the movement.

13. REST TIMER
==================================================

Every exercise should support a rest timer.

DEFAULT:

30 seconds

Controls:

[-10 sec]    [30 SEC]    [+10 sec]

Also:

[SKIP REST]

The user should be able to change the rest period during the workout.

Examples:

30 → 40 → 50 seconds

or

30 → 20 → 10 seconds

The timer must update immediately.

When the timer reaches zero:

- Give a clear visual indication.
- Move the user to the next exercise/set when appropriate.

Do not force the user to wait if they select:

SKIP REST.
